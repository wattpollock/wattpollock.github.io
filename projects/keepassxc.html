KeePassXC Password Manager

KeePassXC is a free, open source password manager that stores every password in one encrypted file on my own computer. I set it up so every account can have its own long, random password, and I only have to remember one master password. Because the database is offline, my passwords are not stored on a company's cloud server.

Terminology

  • Password manager: an app that stores and generates passwords so you do not reuse them across accounts.
  • Database (.kdbx): the single encrypted file that holds all of my entries.
  • Master password: the one password that unlocks the database. It cannot be recovered if forgotten.
  • Entry: one saved login, with a title, username, password, and URL.
  • Group: a folder inside the database used to organize entries, like Homelab.
  • Password reuse: using the same password on several accounts. One breach then exposes all of them.

The following steps detail the KeePassXC setup:

  1. Install KeePassXC
    Download the Windows installer from the official KeePassXC download page and run it with the default install location.
  2. Create a new database
    Open KeePassXC, click Create Database, and give it a name.
  3. Keep the default encryption settings
    The defaults use strong, current encryption, so I left them unchanged.
  4. Set a strong master password
    I chose a long master password that I do not use anywhere else, since it protects every other password in the file.
  5. Organize entries into groups
    I created groups such as Homelab to keep server logins separate from personal accounts.
  6. Add entries with generated passwords
    Press Ctrl+N to add an entry, then click the dice icon to generate a random password. I used this for my Proxmox, Ubuntu VM, and Immich logins.
  7. Copy passwords safely
    Select an entry and press Ctrl+C. KeePassXC clears the clipboard after a few seconds so the password does not stay there.

Security note: Password reuse is one of the most common ways accounts get compromised. A password manager removes the need to reuse passwords, and keeping the database offline means I control where my credentials are stored. The tradeoff is that the master password has no recovery option, so it must be strong and remembered.
