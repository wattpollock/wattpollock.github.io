Immich Photo Server on Proxmox

Immich is a free, self hosted replacement for Google Photos. I installed it in an Ubuntu Server VM on my Proxmox host so my photo library lives on hardware I own instead of a paid cloud subscription. I then uploaded my cleaned up library of about 32,000 photos and videos to it.

Terminology

  • Self hosted: running a service on your own hardware instead of using a company's servers.
  • Docker: a tool that runs apps in isolated packages called containers.
  • Docker Compose: a file that defines several containers that run together. Immich uses four: the server, machine learning, a database, and a cache.
  • Static IP: an address set by hand that never changes, used here because nothing hands out addresses on the VM network.
  • NAT: lets VMs on a private network share the host's internet connection.
  • Port forward: a rule that sends traffic arriving on one port of the host to a VM.
  • API key: a password that lets a program, instead of a person, log in to a service.

The following steps detail the Immich setup:

  1. Download Ubuntu Server to Proxmox
    In Proxmox, go to local, then ISO Images, then Download from URL, and download the Ubuntu Server 26.04 LTS ISO.
  2. Create the VM
    4 CPU cores (type host), 8 GB of RAM, and a 300 GB disk on local-lvm, attached to the private bridge vmbr0.
  3. Install Ubuntu with a static IP
    During install, set the network manually to address 10.10.10.50, gateway 10.10.10.1 (the Proxmox host), and DNS 1.1.1.1. Enable the OpenSSH server.
  4. Install Docker
    curl -fsSL https://get.docker.com | sudo sh
  5. Download the Immich files
    Download docker-compose.yml and example.env from the official Immich install guide, and rename example.env to .env.
  6. Set a random database password
    sed -i "s/^DB_PASSWORD=.*/DB_PASSWORD=$(openssl rand -hex 16)/" .env
  7. Start Immich
    docker compose up -d, then docker compose ps to confirm all four containers are healthy.
  8. Forward port 2283 from the host to the VM
    On the Proxmox host:
    iptables -t nat -A PREROUTING -p tcp --dport 2283 -j DNAT --to-destination 10.10.10.50:2283
    I saved the same rule as a post-up line in /etc/network/interfaces so it survives a reboot.
  9. Create the admin account
    Open http://<host IP>:2283, click Getting Started, and save the password in KeePassXC.
  10. Upload the library with the Immich CLI
    Create an API key in Immich, install the uploader with npm i -g @immich/cli, log in, and upload one folder at a time. The CLI skips anything already uploaded, so it can resume if interrupted.

Troubleshooting

  • Intermittent loss of connection: the host and the VM kept losing internet. Running arp -a showed a different device answering on the host's address. The router had handed the same IP to another device. I moved the host to an unused address, which fixed it.
  • DNS lookups failing: Tailscale had taken over the host's DNS settings. Running tailscale set --accept-dns=false restored normal lookups.
  • Uploader found no files: on Windows, the Immich CLI did not accept full paths with a drive letter. Running it from inside the library folder with one folder name at a time worked.

Security note: Immich is never exposed to the public internet. It is reachable only from my home network and over my private Tailscale network, with no port forwarding on the router. The database uses a randomly generated password, every login is stored in KeePassXC, and I revoked the upload API key once the import finished.
