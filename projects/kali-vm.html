Kali Linux VM on Proxmox

I built a Kali Linux virtual machine on my Proxmox host to use for penetration testing and capture-the-flag (CTF) competitions. Kali comes preloaded with security tools, and running it as a VM keeps it isolated and easy to snapshot or rebuild.

Terminology

  • Kali Linux: a Linux distribution built for penetration testing, preloaded with security and networking tools.
  • VM (Virtual Machine): a full computer running in software on the Proxmox host.
  • Bridge: a virtual network switch in Proxmox that connects VMs to a network.
  • NAT (Network Address Translation): a technique that lets devices on a private network share one outbound connection, rewriting their traffic so it can reach the internet.

The following steps detail the Kali VM setup:

  1. Download the Kali ISO into Proxmox
    In the Proxmox web UI, go to local storage, open ISO Images, and use "Download from URL" with the installer link from the Kali downloads page. This pulls the ISO straight onto the host.
  2. Create the VM
    Click "Create VM" and set it up with the Kali ISO, 4 CPU cores, 8 GB of RAM, and a 60 GB disk. Enable the QEMU guest agent and attach the network device to the default bridge.
  3. Run the installer
    Boot the VM, open the console, and run the Kali graphical installer. Set a username and password, use guided partitioning, and keep the default Xfce desktop.
  4. Update and verify
    After first boot, open a terminal and run sudo apt update && sudo apt full-upgrade -y to get the latest packages and confirm the system is working.

Troubleshooting: No Network on the VM

During the install, the VM failed to get an IP address through DHCP. The cause was the host's network setup: the Proxmox machine is a laptop that connects over Wi-Fi, and the VM was attached to an internal bridge that had no path to the internet. Wi-Fi adapters cannot be bridged the normal way, so the VM had no route out.

I fixed this by giving the VM a static IP on the bridge and enabling NAT on the host, so the VM's traffic routes out through the laptop's Wi-Fi:

  1. Enable IP forwarding on the host
    sysctl -w net.ipv4.ip_forward=1
  2. Add a NAT rule for the VM's subnet
    iptables -t nat -A POSTROUTING -s 10.10.10.0/24 -o wlo1 -j MASQUERADE
    This masquerades the VM subnet's traffic out through the host's Wi-Fi interface (wlo1).
  3. Verify connectivity from Kali
    ping -c3 1.1.1.1 to confirm routing works, then ping -c3 google.com to confirm DNS.

What I learned: A VM is only as connected as the host's networking allows. Because the host used Wi-Fi, a normal bridge could not reach the internet, and NAT was the correct fix to route the VM's traffic out. Working through this taught me how Proxmox bridges, NAT, and IP forwarding fit together.
